# Story 1.2 — Landing e agendamento público

Status: Done

## Objetivo

Abrir a Artspace para o cliente final: landing `/` com identidade da logo, GSAP no scroll, e fluxo de agendamento real (procedimento → profissional → horário → conta). Cliente autenticado não entra em `/app`.

## Acceptance Criteria

- [x] `/` é a landing (não redireciona mais para `/login`)
- [x] Hero, ramos, equipe, contato e CTA de agendar; mobile-first; GSAP com respeito a `prefers-reduced-motion`
- [x] Fluxo: ramo → procedimento → profissional → slots livres → nome/CPF/telefone → confirmação
- [x] Slots = grade − folgas − appointments `scheduled|confirmed|present`
- [x] Agendamento público sem e-mail/senha: nome, CPF e telefone; CPF reaproveita a ficha (sem criar login)
- [x] Login de cliente vai para `/conta` (meus horários); profissional continua em `/app`
- [x] Cliente cancela horário futuro `scheduled|confirmed`; o slot libera
- [x] Conflito de último segundo: “Esse intervalo não está livre.”
- [x] SQL adicional `supabase/public-booking.sql` (auth_user_id + RLS do cliente)
